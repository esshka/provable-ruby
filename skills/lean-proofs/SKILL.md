# Lean proofs for translated Ruby

The definitions live in `<Module>/Code.lean`, generated from the Ruby. Never edit that file and
never restate its definitions; import it and prove things about it. Working references:
`${CLAUDE_PLUGIN_ROOT}/examples/01_money_split/MoneySplit.lean` and
`${CLAUDE_PLUGIN_ROOT}/examples/02_order_flow/OrderFlow.lean`.

Hard rules: no `sorry`, no `admit`, no `native_decide` (it trusts the compiler), no Mathlib.
Every rule ends as PROVEN (a theorem) or REFUTED (a theorem of the form `¬ ∀ ...` with a witness).
Anything the model does not check goes on the `Trust:` line as ASSUMED.

## 1. State the rule first

Write each rule as a named `Prop` with a one-line doc comment in plain words, taken from intent,
not from the code. Get the user's agreement on the wording before proving.

```lean
/-- No cent is lost and no cent is made up. -/
def SumsTo (total : Int) (xs : List Int) : Prop := xs.sum = total

/-- Money and status always agree. -/
structure Valid (o : Order) : Prop where
  refunded_le_paid : o.refunded ≤ o.paid
  paid_in_full : o.status = .paid → o.paid = o.total
```

## 2. Try to break it before you prove it

A grid search finds most false rules in seconds. Run `lake build` once in `proofs/` so the generated
`<Module>.Code` is compiled, then `lake env lean scratch.lean`:

```lean
import MoneySplit.Code
open MoneySplit
#eval Id.run do
  for t in List.range 20 do
    for p in List.range 6 do
      if let .ok xs := remainder_last t p then
        if !xs.all (fun a => xs.all (a ≤ · + 1)) then return some (t, p, xs)
  return none
```

If it finds a witness, write the refutation instead of a proof. If the rule is a named `Prop`
(`NeverNegative …`), `unfold` it first; `decide` and `omega` cannot see through the name:

```lean
-- 11 cents over 4 people gives [2, 2, 2, 5]: the last person pays 3 cents more.
theorem remainder_last_is_not_fair :
    ¬ ∀ total parts xs, remainder_last total parts = .ok xs → Fair xs := by
  intro h
  have := h 11 4 [2, 2, 2, 5] rfl 5 (by decide) 2 (by decide)
  omega
```

## 3. Recipes

**`let` in the generated code.** A Ruby local becomes `let x := …`. After `unfold f`, omega sees the
whole `let` as one opaque term and fails. Add `dsimp only` right after `unfold` (or `split` first,
as the recipes below do) so the goal holds plain terms.

**Guarded function returning `Except`** (each Ruby guard is one `if … else`):

```lean
theorem even_length (h : even total parts = .ok xs) : xs.length = parts.toNat := by
  unfold even at h
  split at h; · contradiction      -- first guard raised
  split at h; · contradiction      -- second guard raised
  injection h with h; subst h
  simp
```

**When it raises** (an `↔` over the guards):

```lean
theorem even_fails_only_on_bad_input :
    (∃ msg, even total parts = .error msg) ↔ parts ≤ 0 ∨ total < 0 := by
  unfold even
  split
  · simp; omega
  · split <;> simp <;> omega
```

**Every element of a mapped list:** `simp only [List.mem_map] at ha; obtain ⟨i, _, rfl⟩ := ha; split <;> omega`.

**Sums over `List.range`:** prove a helper by `induction n` with
`rw [List.range_succ, List.map_append, List.sum_append, ih]`, then `omega`.

**Division facts** (omega cannot multiply two variables): bring them in first, then `omega`:
`have := Int.mul_ediv_add_emod total parts`, `Int.emod_lt_of_pos total hp`, `Int.emod_nonneg _ (by omega)`,
`Int.toNat_of_nonneg (by omega)`.

**State machine invariant** — prove one step, then induct over the events:

```lean
theorem apply_valid (hv : Valid o) (h : apply o e = some o') : Valid o' := by
  obtain ⟨status, total, paid, refunded, seen⟩ := o
  obtain ⟨h1, h2, h3, h4, h5, h6⟩ := hv
  simp only at h1 h2 h3 h4 h5 h6
  cases status <;> cases e <;> simp only [apply] at h <;> (try split at h) <;>
    first | contradiction | (injection h with h; subst h; constructor <;> simp <;> (try split) <;> simp_all <;> omega)

theorem run_valid (hv : Valid o) : Valid (run o events) := by
  induction events generalizing o with
  | nil => exact hv
  | cons e events ih => exact ih (step_valid hv)
```

**Retries are harmless** (idempotence): `unfold step; by_cases hs : e.id ∈ o.seen` then
`simp [hs]` and `cases ha : apply o e <;> simp [hs, ha]`.

**Finite facts** (an enum, a concrete list): `decide` or `rfl`.

## 4. When a proof is stuck

- Read the goal: `lake build` in `proofs/` prints every error with the goal state.
- Try, in order: `omega`, `simp_all`, `split <;> simp_all <;> omega`, `grind`, `exact?`.
- Lemma names change between Lean versions; use `exact?` or `#check @Int.emod_nonneg` instead of guessing.
- If the Ruby changed and old proofs broke, the generated shape changed. Repair the proof; never edit `Code.lean`.
- Still stuck after real attempts? Say which rule is OPEN and why. Do not weaken the rule to make it provable
  without telling the user.
