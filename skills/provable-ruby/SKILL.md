# provable-ruby

A test checks the inputs you thought of. A proof checks all of them. The proof is about a Lean
model; `bin/translate` generates that model from the Ruby, and conformance runs both on the same
inputs, so the model stays tied to the real code.

## Tools

All tools ship in this plugin, at `${CLAUDE_PLUGIN_ROOT}`. Run them with that absolute path from the user's repo.

| Command | Does |
|---|---|
| `ruby ${CLAUDE_PLUGIN_ROOT}/bin/check-style FILE...` | rejects Ruby outside the verifiable subset, with `file:line [rule]` |
| `${CLAUDE_PLUGIN_ROOT}/bin/translate PROOFS` | writes `<srcDir>/<Module>/Code.lean` for each Ruby file in `PROOFS/models.lock` |
| `${CLAUDE_PLUGIN_ROOT}/bin/translate --check PROOFS` | fails if a generated file is out of date |
| `${CLAUDE_PLUGIN_ROOT}/bin/verify PROOFS` | style, translation, `lake build`, drift lock, conformance, counterexamples |
| `${CLAUDE_PLUGIN_ROOT}/bin/verify --relock PROOFS` | rewrites `models.lock` after you re-read the model against changed Ruby |

`${CLAUDE_PLUGIN_ROOT}/examples/01_money_split/` (pure functions) and `${CLAUDE_PLUGIN_ROOT}/examples/02_order_flow/` (a state
machine over events) are complete, working references. Copy their shape.

Requirements: Ruby 3.2+, the `prism` gem 1.2+, and Lean through elan (`lake` on PATH). Check with
`ruby -v`, `ruby -e 'require "prism"; puts Prism::VERSION'`, `lake --version`. If one is missing,
give the user the install command and ask before running it:
`gem install prism` and
`curl -sSfL https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh | sh -s -- -y --default-toolchain none`.

## Workflow

Follow the steps in order. Each has a check; do not go on until it passes.

1. **Pick the core.** One function or one state machine where a wrong answer costs money or
   trust. Pull I/O (ActiveRecord, clock, HTTP, env) into a thin shell that calls a pure module.
   Load the `verifiable-ruby` skill for the rules and the refactor.
   Check: `ruby ${CLAUDE_PLUGIN_ROOT}/bin/check-style path/to/core.rb` prints nothing. The app's own tests still pass.
2. **Write the rules in plain words first,** from intent: what callers need, product rules,
   validations. Never derive a rule only from the code under test; then it proves nothing.
   Show the list to the user before you prove anything; a wrong rule is proven as easily as a right one.
3. **Set up `proofs/`** (once per repo): `lakefile.toml`, `lean-toolchain`, `.gitignore`, and one
   folder per core (see the layout below). Nothing builds yet; the model needs the generated code.
4. **Translate.** Add the `#:` type comments, add the file to `models.lock`, run
   `${CLAUDE_PLUGIN_ROOT}/bin/translate proofs`, then write the model file (below) with its header only.
   Check: translate prints `wrote <srcDir>/<Module>/Code.lean`, and `cd proofs && lake build` succeeds.
   Never edit a generated `Code.lean`; change the Ruby and translate again.
5. **State and prove.** Load the `lean-proofs` skill. Every rule ends as PROVEN or REFUTED.
   Check: `lake build` passes and no `sorry`/`admit` remains.
6. **Write the probe** (`probe.lean` + `probe.rb`) and, for each REFUTED rule, `counterexamples.rb`.
   `counterexamples.rb` runs each witness on the real Ruby, prints `REPRODUCED <theorem>: <what happened>`,
   and must `exit 1` when a witness does not reproduce; bin/verify fails only on that exit code.
7. **Verify.** `${CLAUDE_PLUGIN_ROOT}/bin/verify proofs` must end with `CONFORMS` and `REPRODUCED` lines and exit 0.

## Layout in a user's repo

```
lib/billing/late_fee.rb            the Ruby core (annotated, verifiable Ruby)
proofs/
  lakefile.toml
  lean-toolchain                   copy of ${CLAUDE_PLUGIN_ROOT}/lean-toolchain
  models.lock                      sha256 + path of each verified Ruby file, relative to proofs/
  .gitignore                       .lake/
  late_fee/                        one folder per core = the lean_lib srcDir
    LateFee.lean                   import LateFee.Code; rules, proofs, counterexamples
    LateFee/Code.lean              generated by bin/translate; commit it, never edit it
    probe.lean                     prints `input => output` rows from the model
    probe.rb                       reads the inputs, runs the real Ruby, prints the same rows
    counterexamples.rb             runs each REFUTED witness on the real Ruby (optional)
```

`proofs/lakefile.toml` — one `[[lean_lib]]` per core; `name` must equal the Ruby module name:

```toml
name = "proofs"
defaultTargets = ["LateFee"]

[[lean_lib]]
name = "LateFee"
srcDir = "late_fee"
```

Add a file to the lock from inside `proofs/`: `shasum -a 256 ../lib/billing/late_fee.rb >> models.lock`.

## Model file

```lean
import LateFee.Code

/-!
# Model of `late_fee.rb`

Source: lib/billing/late_fee.rb
The definitions are in `LateFee/Code.lean`, generated by bin/translate.
Trust:
* Ruby `Integer` is Lean `Int`, Ruby `Array` is Lean `List`.
* <every other assumption the model does not check>
-/
namespace LateFee

/-! ## Invariants -/
/-! ## Proven -/
/-! ## Refuted (counterexamples) -/

end LateFee
```

## Probe

The probe is how the model stays honest. `probe.lean` prints one line per input,
`<inputs> => <output>`. Cover every edge (zero, negative, one past each limit, every error path)
plus a dense grid of small values, then add seeded random rows with large values
(`mkStdGen 42`, `randNat`). `probe.rb` reads each line, keeps the part before ` => `, runs the real
Ruby, and prints the same format, rendering `raise ArgumentError` as `error: <message>`. Copy
`${CLAUDE_PLUGIN_ROOT}/examples/01_money_split/probe.{lean,rb}` for plain functions and `02_order_flow` for event
sequences, with two changes for a user's repo:

- The examples keep the Ruby next to the probe. In `proofs/<core>/probe.rb` load the real file by
  its path from there, e.g. `require_relative "../../lib/billing/late_fee"`.
- The examples split inputs on spaces. If an input is a string that can be empty or hold spaces,
  print it quoted in Lean (`s!"\"{s}\""`) and parse it back in Ruby, or the probe skips exactly
  the strings most likely to break the code.

A diff means the model or the translator is wrong until proven otherwise; report it,
never change the Ruby to make a diff go away.

## Report

End with one line per rule, like the examples' README:

```
PROVEN   fee_never_above_cap        the fee is never above 50.00
REFUTED  remainder_last_is_not_fair  remainder_last(11, 4) = [2, 2, 2, 5]
ASSUMED  Ruby divmod and Lean / % agree when the divisor is positive (the probe checks it)
```

A REFUTED rule is not always a bug; it can be a product question. Say which, and let the user decide.
